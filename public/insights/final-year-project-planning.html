How to Choose and Plan a Strong Final-Year Project

A practical framework for selecting a feasible academic project, writing the problem statement, planning requirements, evaluating results and preparing a clear presentation.

Quick answer

Choose a problem you can investigate, confirm that required data and resources are available, define a small working scope, identify measurable evaluation criteria and keep a realistic schedule for implementation, testing and documentation.

Start with a problem worth solving

Describe the user, context and current difficulty. Review existing approaches and identify a specific gap you can investigate. Avoid starting with a technology name and trying to invent a problem around it.

Check feasibility early

Confirm access to data, hardware, APIs, software licences, participants and a suitable development environment. Consider privacy, permissions, ethics approval and the time available. A smaller working system is usually stronger than an unfinished ambitious one.

Write requirements and architecture

Create clear functional and non-functional requirements. Map user roles, important workflows, data entities, interfaces and system boundaries. Use diagrams where they improve understanding, and keep the documentation consistent with the implementation.

Build in milestones

Plan a small prototype, core workflow, integration, testing and final refinement. Keep source code under version control, maintain a task log and capture important decisions. Demonstrate progress before the final weeks.

Evaluate the result

Define how success will be measured. Depending on the project, this may include task completion, accuracy, latency, usability, reliability or comparison against a baseline. Report limitations honestly and do not present a demo as proof of production readiness.

Prepare documentation and viva

Explain the problem, related work, requirements, architecture, implementation, evaluation, limitations and future work. Be ready to justify technology choices, describe failures and show how the system behaves on representative test cases. Follow the institution's rules and keep authorship of your work clear.

Frequently asked questions

Should a final-year project use AI to score highly?

Not necessarily. The project should use technology that fits the problem. A well-designed non-AI system with clear evaluation can be stronger than an AI feature added without purpose.

How can a project scope be kept realistic?

Limit the first release to the most important end-to-end user journeys, agree acceptance criteria and reserve time for testing, documentation and presentation.

What is the role of project mentorship?

Mentorship can help review feasibility, design, implementation choices, testing and communication. Students should remain responsible for their own research, code, decisions and academic submissions.
